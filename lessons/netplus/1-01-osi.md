# OSI model

The OSI (Open Systems Interconnection) model is a **reference model**. It describes network communication as **seven layers**, each with one job. It isn't a protocol you install. It's a shared vocabulary, so people can say "that's a Layer 2 problem" or "a router is a Layer 3 device" and be understood. Network+ uses it everywhere: to classify devices, protocols, attacks, and to structure troubleshooting.

## Why the OSI model matters

- **It splits a complicated process into pieces.** Each layer only has to do its own job and hand data to the layer above or below it.
- **It lets different vendors' equipment work together.** A switch from one company and a NIC from another interoperate because both follow the same layer standards (e.g. Ethernet at Layer 2).
- **It gives you a troubleshooting map.** You can test one layer at a time instead of guessing.
- **It's a model, not an implementation.** Real networks run the TCP/IP suite, which maps onto the OSI layers.

## The seven layers

Numbered from the bottom (closest to the wire) to the top (closest to the user):

| # | Layer | Its job | Examples |
|---|---|---|---|
| 7 | **Application** | Network services that applications use | HTTP, DNS, SMTP, FTP, SSH, DHCP |
| 6 | **Presentation** | Data format: encoding, **encryption**, compression | TLS/SSL (per CompTIA), ASCII, JPEG |
| 5 | **Session** | Opens, manages, and closes sessions (dialog control, checkpoints) | RPC, NetBIOS sessions |
| 4 | **Transport** | End-to-end delivery between hosts, **port numbers**, reliability | TCP, UDP |
| 3 | **Network** | **Logical (IP) addressing** and **routing** between networks | IP, ICMP, IPsec, routers |
| 2 | **Data Link** | **Framing**, **MAC addressing**, delivery on the local network | Ethernet, 802.1Q VLAN tags, switches, ARP |
| 1 | **Physical** | Raw **bits** as electrical, light, or radio signals; cables and connectors | Cables, connectors, hubs, repeaters, transceivers |

> **Memory tip:** from Layer 1 up: **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way (Physical, Data Link, Network, Transport, Session, Presentation, Application). From the top down: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing.

A few details worth knowing:

- **Layer 4:**
  - **TCP** gives reliable, ordered delivery: handshake, sequence numbers, acknowledgments, retransmission, and **flow control (windowing)**.
  - **UDP** is fast and connectionless.
  - Layer 4 also **segments** large application data into smaller pieces.
- **Layer 2:** has two sublayers.
  - **LLC** (Logical Link Control) talks to Layer 3.
  - **MAC** (Media Access Control) handles hardware addresses and access to the medium.
- **Layer 1:** covers voltages, pinouts, light, radio signals, and cable specifications. It doesn't understand addresses.

## Encapsulation and PDUs

When a host sends data, it travels **down** the stack. Each layer adds its own **header** (Layer 2 also adds a **trailer**). This is **encapsulation**. The receiving host strips them off in reverse order going **up** the stack: **decapsulation**.

| Layer | PDU (protocol data unit) name |
|---|---|
| 5–7 | Data |
| 4 | **Segment** (TCP) / **Datagram** (UDP) |
| 3 | **Packet** |
| 2 | **Frame** |
| 1 | **Bits** |

- **The frame trailer** holds the **FCS (frame check sequence)**, a CRC value the receiver uses to detect corrupted frames. That's why "CRC errors" point to physical problems.
- **Order of wrapping:** application data → wrapped into a segment (ports added) → a packet (IP addresses added) → a frame (MAC addresses and FCS added) → sent as bits.

## Addresses and devices by layer

**Which address lives at which layer:**
- **Port number** → Layer 4 (identifies the application, e.g. 443).
- **IP address** → Layer 3 (logical, routable, identifies the host's network location).
- **MAC address** → Layer 2 (hardware address, used for delivery on the local segment).

**Which device works at which layer:**

| Device | Layer(s) | Why |
|---|---|---|
| Hub, repeater, media converter, cable | 1 | Repeat or carry bits; no address awareness |
| Switch, bridge, wireless access point | 2 | Forward frames by **MAC address** |
| Router | 3 | Forwards packets by **IP address** between networks |
| Layer 3 (multilayer) switch | 2 and 3 | Switches within VLANs **and** routes between them |
| Stateful firewall / packet filter | 3–4 | Filters by IP addresses and ports |
| Next-generation firewall, Layer 7 load balancer, proxy | Up to 7 | Inspects application content (URLs, apps) |

## The TCP/IP model

The TCP/IP (Internet) model has **four layers** and is how real networks are built. It maps onto OSI like this:

| TCP/IP layer | OSI layers |
|---|---|
| Application | 7, 6, 5 |
| Transport | 4 |
| Internet | 3 |
| Network access (link) | 2, 1 |

Exam questions almost always use **OSI** numbering. When someone says "Layer 3", they mean the OSI Network layer.

## Troubleshooting with the OSI model

- **Bottom-up (1 → 7):** start with cables, link lights, and power. Best when **connectivity is completely down**. Example: no link light → Layer 1.
- **Top-down (7 → 1):** start with the application. Best when **one app fails but the network seems fine**. Example: one website shows an HTTP 500 error → Layer 7.
- **Divide and conquer:** start in the middle, usually with **ping (Layer 3)**.
  - Ping succeeds → Layers 1–3 work, so look higher.
  - Ping fails → look lower.
- **Placing common problems:**
  - Bad cable or connector → **Layer 1**.
  - MAC flooding, ARP spoofing, VLAN problems, duplex mismatch symptoms (CRC errors on frames) → **Layer 2**.
  - Wrong IP, gateway, or routing → **Layer 3**.
  - A port blocked by a firewall → **Layer 4**.
  - Expired certificate or encryption mismatch → **Layer 6** (CompTIA's view).
  - Application error → **Layer 7**.

## Common mix-ups

- **Packet vs frame vs segment:** **frame = Layer 2**, **packet = Layer 3**, **segment = Layer 4**. Routers move *packets*; switches move *frames*.
- **Session vs Transport:** Transport (4) delivers data between hosts with ports and reliability. Session (5) manages the *conversation* between applications (opening, checkpoints, closing).
- **Presentation vs Application:** encryption, compression, and character encoding are **Layer 6**. The protocol the app speaks (HTTP, DNS) is **Layer 7**.
- **Switch vs router layer:** a normal switch is **Layer 2**. Only a *Layer 3/multilayer switch* routes.
- **Hub vs switch:** a hub (Layer 1) repeats bits out every port. A switch (Layer 2) learns MACs and forwards only where needed.
- **Numbering direction:** Layer 1 is Physical (bottom), not Application.
- **"Data link" vs "network":** MAC addresses are Data Link (2); IP addresses are Network (3).

## Key terms

- **Encapsulation / decapsulation:** adding headers going down the stack / removing them going up.
- **PDU:** the name for data at a layer: data, segment/datagram, packet, frame, bits.
- **FCS / CRC:** the error-check value in the frame trailer.
- **LLC / MAC sublayers:** the two halves of the Data Link layer.
- **Windowing:** TCP flow control that limits unacknowledged data in flight.
- **Reference model:** a conceptual framework (OSI) rather than software you run.

> **Exam tip:** Expect to name the layer for a device, protocol, PDU, address type, or symptom. Routers = 3, switches = 2, hubs = 1, encryption = 6, ports = 4.
